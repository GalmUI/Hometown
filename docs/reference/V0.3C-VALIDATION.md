# v0.3c — Development Navigation and Housing Privacy

Version `0.3.0-alpha.3`; Minecraft 1.21.1 / NeoForge 21.1.250 / Java 21. The extended packet requires protocol 4 and matching client/server JARs. Town data needs no migration.

## Continuation audit

The interrupted implementation already contained all requested runtime features, compiled 36 sources, and passed 85 tests. This continuation preserved those changes, reviewed the current working files, added a Residents-pagination regression across Development subnavigation, reran compilation/tests, and completed release documentation and packaging. There is no Git repository metadata in the workspace or project folder; the working files were compared against the saved v0.3b source ZIP instead.

The v0.3a room detector and room debug command, founding, persistence, population scan, bed query, and server Ledger refresh service remain unchanged from v0.3b. Changes are confined to Development presentation, Housing density/Privacy aggregation and DTO, its wire format, debug output, translations, version metadata, and tests/documentation.

## Implemented behavior

- Primary Overview, Residents, Development, and History navigation remains independent of the DevelopmentSection enum.
- Development has six smaller parchment bookmarks. Housing is the initial selection; the selection is retained when switching main tabs. The selected subsection has an underline. Subnavigation neither recreates the screen nor sends a new snapshot request.
- Housing owns both pages: Supply on the left, Privacy and room counts on the right. Each other category owns a separate placeholder spread without Housing data or calculations.
- SHORTAGE replaces OVERCROWDED for supply. Existing population, enclosed-bed capacity, unhoused, spare, total-bed, and unsealed-bed semantics are retained.
- The server classifies the full detected room's bed count: PRIVATE = 1, SHARED = 2, CROWDED = 3–4, HIGH_DENSITY = 5+. It aggregates room counts and town-relevant bed counts in each category above the unchanged detector.
- Privacy is the nearest-integer average of 100/80/60/40 points per enclosed bed by category. The server calculates and transmits the score; rendering does not run density aggregation or world queries. All enclosed beds still provide capacity.
- Zero enclosed beds means Privacy N/A. Zero residents means capacity N/A; Privacy still describes existing enclosed rooms if beds remain. Incomplete scans suppress both scores and numerical Housing diagnostics.
- Two static native-pixel bars represent available values from 0 to 100. N/A values have no bar. All layout and bar coordinates are integers, with no pose/font scaling and the existing single background-blur pass.
- `/hometown debug housing <uuid>` now includes Privacy and all four room/bed categories. `/hometown debug room` is unchanged.

Room membership continues to use the same scan-local cache and work limits. Out-of-town beds may influence a room's density classification, but only qualifying town bed POIs contribute to the town's weighted Privacy and capacity. No persistent room/Housing records, background work, gameplay consequences, Comfort, furniture scanning, or other Development mechanics were introduced.

## Tests and build

86 tests pass, with no failures, errors, or skips. This includes all previous tests, nine Privacy tests, and a focused pagination/navigation regression. Tests cover density thresholds; adding/removing real Minecraft bed block states; 95% weighted Privacy; perfect Privacy with a supply shortage; high density with full supply; broken/repaired windows; empty, unoccupied, and incomplete cases; rounding; and packet round trips for every density category.

Screen tests cover all six Development pages, default selection, selected underline, hidden secondary controls outside Development, no extra network requests during navigation, independent capacity/Privacy text, placeholders, and Residents paging after a subpage switch. Recorded rendering at GUI sizes equivalent to scales 2, 3, and 4, plus the minimum viewport, verifies bounds and the unchanged native-pixel/blur ordering.

36 main Java files compile without errors. The only compiler output is the two pre-existing client event-bus annotation deprecation warnings. Standard `gradlew.bat build --offline` was attempted during this implementation and failed before mod compilation in Minecraft artifact extraction with the existing Windows `AccessDeniedException`. The final JAR is compiled and packaged with the same direct JavaCompiler route used for the previous working versions. Packaging checks metadata, JSON/translations, Java 21 classes, archive integrity, and exclusion of Minecraft/test dependencies.

The automated worlds use real Minecraft block states with mocked loaded-chunk storage, and the UI uses a recording graphics backend. They are not a live Minecraft village, GPU screenshot test, or server performance benchmark. The requested real-village v0.3c playtest remains pending; see ACCEPTANCE.md. Earlier room/Housing behavior was confirmed in-game by the user.
